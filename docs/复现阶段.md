# 项目背景
+ Option 5: KV Cache Management Optimization for LLM Inference
+ Reproduce and profile KV cache offloading across multiple storage tiers, such as CPU DRAM, SSDs, and peer GPUs HBM, and optimize the KV Cache offloading process.
+ Optimize KV Cache offloading strategies for specialized workloads (e.g., agentic workloads), or improve KV Cache transfer efficiency across different storage tiers by exploiting the characteristics of their data paths.
+ Improve TTFT, throughput, etc.

# 符号、指标、出图说明
## 测试指标
以下指标应尽量在实验中进行记录

**延迟相关**

+ TTFT: time-to-first-token
+ ITL: inter-token-latency
+ E2E: end-to-end
+ Prefill time
+ Decode time

**吞吐量相关**

+ Request Throughput: req/s= $ N_{completed} $/ $ T $. (单位时间内系统成功处理的请求数量 (req/s))
+ Output Token Throughput
+ Total Token Throughput
+ Prefill Throughput
+ Peak Output Throughput

**cache 相关**

+ kv cache usage perc (`vllm:kv_cache_usage_perc`): 已使用的KV缓存块所占的**比例**
+ gpu cache usage perc
+ cpu cache usage perc
+ prefix cache hits：前缀缓存**命中**的累计次数，以**命中的Token数量**为单位
+ prefix cache queries：前缀缓存**查询**的累计总次数，以**查询的Token数量**为单位
+ external_prefix_cache_hits (外部命中)
+ external_prefix_cache_queries

**offload 相关**

+ kv_offload_total_bytes (Counter): 卸载操作传输的总字节数。通过 `transfer_type` 标签区分方向 (`cpu_to_gpu`, `gpu_to_cpu`)。
+ kv_offload_total_time(Counter): 所有卸载操作的总耗时。同样带 `transfer_type` 标签。
+ kv_offload_size (Histogram): 单次卸载操作传输的数据量（字节）分布。可用于分析传输批次大小，带 `transfer_type` 标签。
+ effective transfer bandwidth: $ \frac{CPU \to GPU bytes}{CPU\to GPU time} $
+ 该部分应尽量多一点

## Workload
### Benchmark 1：Normal Workflow
使用 vllm 自带 bench serve 的两种模式：random 或者 **prefix_repetition**（主要是后者），sglang 同理

**实验配置**

+ ID
+ mode (random / **prefix_repetition**)
+ ISL / OSL: 建议 1-4K/128，可根据实际KV cache负载决定
+ prefix / suffix
+ QPS：建议 0.05/0.1/0.25/0.5/1；Poisson
+ Concurrency：1-8

### Benchmark 2：Agent workflow
建议之一是 BFCL v4，亦可自行构造数据集，可参考论文：[[2606.00866v1] Idleness is Relative: Exploiting Tool-Call Idle Windows for Offloading in Agentic Systems with MORI](https://arxiv.org/abs/2606.00866v1)

### Benchmark 3
发现或构造具有挑战性的 benchmark，围绕项目研究核心，提出现有不足，发现优化点

## 指标记录
首先应当至少包含 [指标](#符号、指标、出图说明)，一个 AI-gen 的案例如下，仅作参考：

| 类别 | 指标 | 具体定义 |
| --- | --- | --- |
| 延迟 | TTFT、ITL、E2E、Prefill、Decode | 全部记录 p50/p95/p99；TTFT 包含排队、KV loading 和 prefill |
| 延迟补充 | Queue time | 请求进入服务到首次被调度的时间 |
| 延迟补充 | KV load stall | 请求因所需 KV 尚未从 CPU/SSD 返回而阻塞的时间 |
| 吞吐 | Request throughput | 完成请求数 / 测量时间 |
| 吞吐 | Output throughput | 实际生成 token / 测量时间 |
| 吞吐 | Logical total throughput | 原始 input token + output token / 时间 |
| 吞吐 | Physical throughput | 实际重新计算的 prefill token + output token / 时间 |
| 吞吐 | Prefill throughput | 实际计算的非命中 prompt token / prefill compute time |
| 吞吐 | Peak output throughput | 1 秒滑动窗口内的最大 output token/s |
| Cache | GPU usage | GPU 已用 KV blocks / GPU 总 blocks |
| Cache | CPU usage | CPU 已用 KV blocks / CPU 总 blocks；若框架未提供则自行计算 |
| Cache | Local hit rate | Δprefix_hits/Δprefix_queries\Delta prefix_hits/\Delta prefix_queries |
| Cache | External hit rate | Δexternal_hits/Δexternal_queries\Delta external_hits/\Delta external_queries |
| Cache 补充 | Eviction rate | 每秒从 GPU 驱逐的 KV blocks/tokens |
| Cache 补充 | Recompute tokens | 因缓存未命中而重新 prefill 的 token 数 |
| Cache 补充 | Reuse distance | 两次访问同一 prefix 之间经过的请求数或 token 数 |
| Offload | Bytes/time/size | 分 CPU→GPU、GPU→CPU；Counter 使用实验前后差值 |
| Offload | Effective bandwidth | Δbytes/Δtransfer time\Delta bytes/\Delta transfer\ time，两个方向分别报告 |
| Offload 补充 | Overlap ratio | 被 prefill/decode 覆盖的传输时间 / 总传输时间 |
| Offload 补充 | Load amplification | 实际加载字节 / 本次真正命中的 KV 字节 |
| 服务质量 | Goodput | 同时满足 TTFT、ITL SLO 的完成请求数 / 秒 |
| Agent | Workflow makespan | 一个完整 workflow 从第一步开始到最后一步结束 |
| Agent | Steps/calls per episode | 每个任务实际工具步骤数和模型调用数 |
| Agent | Tool wait time | 工具执行和环境交互时间 |
| Agent | Task success | BFCL 官方成功率或 LongBench 官方得分 |
