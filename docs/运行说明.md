# 运行说明

## 1. 直接查看与离线复算

先进入本交付包根目录。HTML报告完全离线，Markdown与CSV均保留；只做数据验收无需第三方Python包或GPU：

```bash
python3 -B scripts/verify_delivery.py
```

需要重新画图时，在自己选择的虚拟环境安装依赖（安装会写环境，不会占GPU）：

```bash
python3 -m venv .venv-analysis
.venv-analysis/bin/python -m pip install -r requirements-analysis.txt
MPLCONFIGDIR="$PWD/.cache/matplotlib" XDG_CACHE_HOME="$PWD/.cache" .venv-analysis/bin/python -B scripts/analyze_v100_experiment.py raw --output recomputed --plot
.venv-analysis/bin/python -B -m pytest tests -q
```

`recomputed/`是新的分析产物目录，`raw/`不修改。`summary.csv`中的source相对于raw目录。主指标计算使用stdlib；NumPy/Matplotlib只用于绘图相关依赖。

## 2. 原实测源码与便携入口

`run_v100_experiment.py`、`smoke_v100.py`、`v100_observer.py`保持实测时的字节不变，其SHA256与各组environment.json一致。原文件中的绝对路径、下载逻辑、早期审批提示属于历史运行入口；**不要在陌生机器直接运行smoke_v100.py的main**，它会下载模型、启动早期探针并可能覆盖历史smoke日志。

`parallel_v100_experiments.py`是本次追加S1/S2的历史启动器，记录了当时GPU UUID与端口，保留用于审计；不要把它当成任意机器上的通用启动入口。

新实验使用`reproduce_v100.py`，它只改变根目录、模型路径、GPU选择与端口，导入同一份测量逻辑。默认只打印计划；显式`--execute`才校验模型并运行。为避免覆盖历史数据，work-root必须不存在。`--baseline all`默认在同一张卡串行跑三组；这属于新一轮测量，不是本报告三卡并行记录的复制。

## 3. 在已验证的nju-gpu环境重跑

原环境：`/root/beamforming/CV/v100-probe/.venv/bin/python`；原模型：`/root/beamforming/CV/v100-probe/models/Qwen2.5-3B-Instruct`。

在服务器交付包根目录，先只检查计划（不使用GPU、不创建文件）：

```bash
/root/beamforming/CV/v100-probe/.venv/bin/python -B scripts/reproduce_v100.py --work-root /root/beamforming/CV/rerun-v100-01 --model /root/beamforming/CV/v100-probe/models/Qwen2.5-3B-Instruct --gpu 0
```

明确要重跑后，在同一命令后增加`--execute`。只测某一组可增加`--baseline S2`；先测独立18请求回载探针可增加`--pilot`，同样需使用新work-root。

若希望新一轮三卡同时跑，在三个终端中分别使用`--baseline S0/S1/S2`、`--gpu 0/1/2`、`--port 30171/30172/30173`和**三个不同的work-root**。当前交付分析器按一套raw目录读取结果；各自重跑结果默认不自动合并，避免误把不同轮次混成正式对照。

所有新服务器路径继续放在`/root/beamforming/CV`下。不要删除原始记录、修改SEDS环境，或手工结束其他任务进程。

## 4. 在其他机器安装的注意事项

GPU运行要求Linux、V100-SXM2-32GB、兼容NVIDIA驱动、Python3.12。关键版本：torch2.6.0+cu124、triton3.2.0、sglang0.4.6.post5、sgl-kernel0.1.4、transformers4.51.1、flashinfer-python0.2.5、numpy1.26.4、aiohttp3.14.3。完整包版本见`raw/provenance/packages-snapshot.txt`。

该快照是**环境记录，不是已验证的全新安装锁文件**。原环境通过.pth只读借用了已有SEDS的torch/triton；本次pip check通过，但没有执行全新机器从零安装。不提供“任意新机一条命令必成功”的保证。历史`bootstrap_v100_probe.sh`仅适用于原服务器，不作为通用安装脚本交付。

中国大陆环境可从ModelScope官方`Qwen/Qwen2.5-3B-Instruct`下载模型，从阿里云PyPI镜像安装普通依赖；CUDA专用wheel仍可能需要相应官方wheel源。不要将模型换成GPTQ/AWQ/BF16配置，或擅自升级SGLang。重跑入口会验证所有模型文件SHA256；若上游master变更导致不匹配，应先定位对应版本，不能跳过指纹检查。

## 5. 报告生成与依赖边界

`build_v100_report.py <交付包根目录>`会从raw复算结果，并生成报告Markdown、artifact.json及offload图；修改报告源稿使用同目录`v100_report_template.md`。它会更新report及部分results文件，运行后应重新生成SHA256清单。

HTML为既有artifact的自包含构建产物。构建使用Codex Data Analytics 0.2.10-13ceeea1f599随附的`deliver_portable_artifact.mjs`；该第三方报告构建工具未在交付包内重分发。包内HTML可直接使用，原始数据复算、PNG重绘、Markdown重建不依赖此插件。HTML视觉生成工具链不属于GPU算法复现前提。

## 6. 数据与文件安全

请求文本来自随机token合成器，不是个人语料。raw中保留原始响应、events、Prometheus快照和进程日志；仅分析JSON/JSONL，不执行raw中的launch.py，也不读取或反序列化pickle缓存。模型权重、虚拟环境、下载缓存、SSH配置、凭证和其他项目文件均不包含在包内。
